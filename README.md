# Итоговое практическое задание: сервис доставки еды (база данных)

## Описание задания
**Задача:** реализовать логическую и физическую схемы базы данных, функционал по генерации тестовых данных и функционал по автоматизации для сервиса по онлайн-заказу еды.

---

## Настройка окружения и схемы
1. В базе данных `postgres` создайте схему в формате: `фамилия_на_латинице_в_нижнем_регистре_food`.
   * *Пример:* `khashchanov_food`
   * В этой схеме создаются таблицы, типы данных, функции, процедуры и иные объекты.
2. Создайте схему `exts`, в которую установите модуль `uuid-ossp` для генерации UUID.
3. Для формирования списка значений в атрибутах типа `status` используйте конструкцию: 
   ```sql
   CREATE TYPE … AS ENUM
   ```

### Права доступа (Пользователь)
Для доступа к данным в базе создайте пользователя:
* **Логин:** `reviewer`
* **Пароль:** `NetoSQL2026`
* **Права:**
  * Полный доступ на созданную схему (например, `khashchanov_food`).
  * К `information_schema` и `pg_catalog` — права **только на чтение**.
  * Предусмотреть доступ к схеме `exts`, если этого требует реализованная логика.

## Проектирование физической схемы
Реализуйте физическую схему на основе концептуальной схемы.
* Все идентификаторы должны иметь тип данных **`uuid`**.
* Все отношения должны быть **нормализованы**.
* Все отношения при необходимости должны быть **детализированы**.
* Сформированы все необходимые связи **многие ко многим**.
* Указаны все необходимые **ограничения**.

> **Важно:** Нарушать требования бизнес-логики недопустимо — всё остальное на ваше усмотрение.

## Работа с данными

### 1. Генерация тестовых данных
Реализуйте процедуру `insert_test_data(value)`, которая принимает на вход целочисленное значение. Данная процедура должна внести:

* **`value * 1`** строк случайных данных в таблицы: `clients`, `courier`, `product_category`, `restaurant`.
* **`value * 5`** строк случайных данных в таблицы: `address`, `product`, `order`, `review`, `payment`.
* В таблицы со связями генерируется необходимое количество строк.
* В таблицу `courier_pay` идет отдельная логика генерации данных в соответствии с примером (ссылка в конце описания задания).

**Правила генерации:**
* Генерация `id` должна быть через `uuid-ossp`.
* Генерация символьных полей должна соответствовать размерности типа `varchar`. Если указан тип `varchar(50)`, генерируйте значение от 1 до 50 символов.
* Генерация даты и времени формируется **за последние 6 месяцев**.
* Генерацию статусов можно реализовать через `enum_range()`.
* **Должна отсутствовать** генерация пустых значений.

### 2. Удаление данных
Реализуйте процедуру `erase_test_data()`, которая будет удалять тестовые данные из всех отношений. При этом все данные в БД будут являться тестовыми.

## Автоматизация и бизнес-логика

### Триггеры
* Реализуйте триггер и триггерную функцию `rating_change()`, которая производит расчёт рейтингов блюд, заведений или заказов после того, как пользователь оставляет отзыв.

### Функции
Реализуйте функцию `get_statistic()`, которая возвращает таблицу согласно следующей структуре:
* `restaurant_name` — название ресторана.
* `best_product_name` — название блюда, которое чаще всего покупают в ресторане. Если таких несколько, вывести одно случайное.
* `total_amount` — общая стоимость, на которую куплено в ресторане.
* `avg_amount` — средняя стоимость, на которую куплено в ресторане.
* `best_user` — ФИО клиента, который чаще всего покупает в ресторане. Если таких несколько, вывести одного случайного.

> **Важно:** Если названия столбцов возвращаемой таблицы будут отличаться от указанных выше, приложение работать не будет. Также будет проверяться оптимизация логики.

### Процедуры
1. `add_product(атрибуты таблицы product)` — принимает на вход аргументы согласно структуре таблицы `product` и вносит данные в неё.
2. `courier_salary()` — подсчитывает количество доставок по курьеру для расчета процентной ставки на следующий месяц, а также рассчитывает размер оплаты по курьеру за расчетный месяц. 
   * *Примечание:* Новую ставку нужно внести в структуру (данный момент не был учтен в схеме), а размер оплаты курьеру внести в таблицу `courier_pay`.

### Представления (Views)
* Создайте представление `how_much_money`, которое будет хранить отчет следующего формата (используя рекурсию).
